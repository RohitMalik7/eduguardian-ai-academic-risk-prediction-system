About EduGuardian AI
AI Academic Risk Prediction & Early Intervention System

EduGuardian AI is a full AI-enabled academic risk monitoring system developed for ICT304 - AI System Development at Murdoch University Dubai. The system helps staff identify students who may be at risk of failing by combining deterministic academic performance analysis with a trained machine learning model.

Project Title
AI Academic Risk Prediction & Early Intervention System
System Name
Early Academic Risk Prediction Engine
Core Stack
Flask · SQLite · HTML/CSS/JS · Python ML
Target Outcome
Early warning + explainable intervention support
How to Use Both Portals
Staff and student workflow guide
Staff Portal
  1. Create or edit a unit and configure assessment weights.
  2. Activate the unit so students can access it.
  3. Add or import students and upload grade data.
  4. Open the model configuration panel to review or adjust hybrid weights and risk thresholds if needed.
  5. Run the AI model to generate cohort risk predictions. Before execution, staff can optionally adjust hybrid weights and risk thresholds through a configuration dialog. If unchanged, the system uses validated default values.
  6. Review cohort dashboards, individual student breakdowns, and export reports.
Student Portal
  1. Log in with the assigned student demo account.
  2. Open the Overview and My Units pages to see the unit made available by staff.
  3. View assessment marks and current academic status released through the portal.
  4. Check the AI-generated risk level, trend direction, and recommendations after staff runs the model.
  5. Download the personal risk status PDF report once the latest model run is available.
AI Architecture - Hybrid Decision Engine
Explainable deterministic logic combined with trained ML inference

The core intelligence of EduGuardian AI is a hybrid architecture that combines two complementary AI signals. This design improves robustness, preserves interpretability, and allows staff to understand why a student has been flagged.

Signal 1 - Deterministic Risk Engine
Rule-based logic implemented in risk_engine.py. It analyses quiz score trends using linear regression, scores assignment performance, fuses both into a deterministic risk score, and generates human-readable intervention alerts. This signal is always explainable.
Signal 2 - ML Model
Trained Random Forest classifier implemented through predict.py and loaded from risk_model.joblib. It was selected after comparing Logistic Regression, Random Forest, and XGBoost using F1-score on the at-risk class.
The two signals are fused using a weighted average.

Default Configuration
ML Weight: 0.55  |  Deterministic Engine: 0.45
Medium Threshold: 0.35  |  High Threshold: 0.55

These values are validated defaults and preserve the original system behaviour. Staff can optionally adjust these parameters at runtime when executing the model, allowing flexible decision boundaries without retraining the ML model.

Risk Level Mapping
  • HIGH RISK - Score ≥ configured high threshold
  • MEDIUM RISK - Score between configured medium and high thresholds
  • LOW RISK - Score below configured medium threshold
HIGH RISK
Hybrid score ≥ configured high threshold. Clear declining trend or severe performance weakness detected. Immediate staff intervention is recommended.
MEDIUM RISK
Hybrid score between configured medium and high thresholds. Early warning signs are present. The student should be monitored closely and contacted if performance declines further.
LOW RISK
Hybrid score < configured medium threshold. The student is currently performing adequately based on the available data.
AI Sub-Systems
Functional breakdown of the full system
1. Data Preprocessing - Loads, cleans, and merges 5 datasets. Applies SMOTE to balance the at-risk class and outputs merged_training_data.csv. (preprocess.py)
2. Model Training & Comparison - Trains and tunes Logistic Regression, Random Forest, and XGBoost, then selects the best model by F1-score on the at-risk class. (train_model.py)
3. Quiz Trend Analyser - Uses linear regression on quiz scores to detect Improving, Stable, or Declining trends and computes a normalised quiz risk score. (risk_engine.py)
4. Assignment Risk Scorer - Computes a normalised risk score from submitted assignment marks and returns 0.5 neutral if no assignments are available yet. (risk_engine.py)
5. Combined Decision Engine - Fuses quiz risk (60%) and assignment risk (40%) into a deterministic risk score classified as LOW, MEDIUM, or HIGH. (risk_engine.py)
6. Hybrid Prediction Engine - Fuses deterministic engine score and ML probability using a weighted hybrid configuration. Default weights are 45% deterministic and 55% ML, but these can be adjusted at runtime by staff when running the model. (predict.py)
7. Alert & Recommendation - Translates risk levels into structured staff alerts with reasons and recommended intervention actions. (risk_engine.py)
8. Report Logger - Saves timestamped JSON audit reports to the reports/ folder for traceability and later review. (risk_engine.py)
Training Datasets
Sources used to build the ML pipeline

The ML model was built using five datasets that cover multiple student performance factors, assessment results, and learning analytics behaviours.

Dataset 1 - Students Grading (Biased) Dataset 2 - Student Performance Prediction Dataset 3 - Student Performance Factors Dataset 4 - Student Quiz Marks Dataset 5 - OULAD (Open University Learning Analytics)
After merging the training data, SMOTE was applied to balance the at-risk class and reduce majority-class bias.
